# question-bank（题库系统）

## 1. 定位

题库全生命周期管理：录入 → 审核 → 发布 → 使用 → 下架。题目是考试（`exam-engine`）与知识库（`rag-knowledge-base`）的共同上游。

## 2. 题目模型（要点）

```
question            题目（题型/题干/选项/答案/解析/难度/来源/状态/版本）
question_kp         题目-知识点多对多（证书/课程/章节归属随知识点获得）
```

- 题型：单选、多选、判断、填空、简答、案例分析（枚举走字典，`database-design`）。
- **每题必须有解析**：AI 答疑（`ai-tutor`）与错题讲解依赖解析；无解析不得发布。
- 来源标记：真题 / 模拟题 / 自编；**真题发布状态受控**（未公开真题禁止 AI 直接泄露答案，见 `ai-tutor`）。
- 难度：易/中/难（组卷配额与掌握度计算使用）。

## 3. 状态机与审核流（强制）

```
草稿 → 待审核 → 已通过(发布) → 已下架
            ↘ 已驳回（附理由，可重新编辑）
```

- 审核流角色分离：录入员（教师/编辑）与审核员（`permission-rbac`）。
- 审核操作必须审计日志；批量审核需列出明细确认。
- 下架：不影响历史试卷（快照机制，`exam-engine`）；知识库索引同步下线（`rag-knowledge-base`）。

## 4. 版本与快照（强制）

1. 题目修改 → 新版本号（`question` 表 version 字段或版本表），历史版本可追溯。
2. 考试引用快照，不引用当前题（`exam-engine`）。
3. 已发布题目的修改必须重新走审核（发布后修改 → 新草稿版本 → 审核 → 再发布）。

## 5. Excel 导入/导出（强制）

- 统一模板（题型/题干/选项/答案/解析/难度/知识点/来源）；模板版本化。
- 导入校验：必填、选项去重、答案合法性（答案必须在选项内）、知识点存在性、重复题检测。
- 校验失败：**逐行错误报告**（行号 + 原因），全部校验通过才入库；禁止部分入库。
- 导入为异步任务（大批量），进度可查、失败可重试、结果可下载。

## 6. 质量指标

- 统计每题：正确率、难度校准（实际 vs 标注）、区分度。
- 低质题（正确率异常、零解析、长期零使用）生成下架建议，人工决策。
- 指标数据供组卷优化与 `learning-profile` 参考。

## 7. 权限

- 教师：自己负责课程范围内的题库（DataScope，`permission-rbac`）。
- 审核员：审核权限点独立（`question:question:audit`）。
- 学员：不可见答案与解析之外的受控信息（解析可见性按配置）。

## 8. 禁止事项（NEVER）

- 无解析的题目发布上线。
- 发布后直接改题（必须新版本 + 重新审核）。
- 导入部分成功部分失败不入明细。
- 下架/修改破坏历史考试数据。
- 未公开真题答案向用户/AI 直接开放。

## 9. 与其他 Skill 的关系

- 考试快照：`exam-engine`；知识库入索引：`rag-knowledge-base`；权限：`permission-rbac`；导入异步任务：`backend-development`。
