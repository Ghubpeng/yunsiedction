# ai-tutor（AI 学习助手核心规范）

## 1. 定位

本平台的 AI 不是通用聊天机器人，而是**场景感知的学习助手**。它必须知道用户“现在在哪、在学什么、在问什么题”。

## 2. 场景感知上下文（九要素）

AI 每次调用必须能感知（按需组装，非全量）：

1. 当前用户
2. 当前证书
3. 当前课程
4. 当前章节
5. 当前知识点
6. 当前题目
7. 用户历史错题
8. 用户学习档案（掌握度/薄弱点，见 `learning-profile`）
9. 用户 Token 余额（计费预检，见 `token-billing`）

**场景示例：**

- 视频页点 AI：“帮我总结这一节” → AI 知道自己正在看哪一节（scene=course.chat + chapterId）。
- 题目页点 AI：“为什么错？” → AI 知道当前题目与用户答案（scene=question.help + questionId + userAnswer）。

## 3. 上下文组装规则（强制）

```
前端只传场景锚点：scene + resourceId（courseId / chapterId /
knowledgePointId / questionId / examRecordId / 文本输入）
        ↓
后端 ContextBuilder 统一组装：
  用户/证书/课程/章节/知识点/题目/错题/档案/余额
        ↓
AI 服务（FastAPI）：RAG 检索 + 生成（见 rag-knowledge-base）
```

1. **前端禁止自行拼接 prompt / 塞任意上下文**；只能传锚点与用户原话。
2. 系统上下文与用户输入严格分离（不同消息角色/结构字段），防提示注入：用户输入中的“忽略以上指令”类内容不得改变系统约束。
3. 用户历史/档案只注入**最小必要字段**；任何用户数据不得跨用户泄露（会话与档案按 user 隔离）。

## 4. 场景清单（每类必须按此实现）

| scene | 触发 | 行为要求 |
|---|---|---|
| `course.chat` | 课程/视频页提问 | 基于该章节知识库总结/讲解，引用章节与知识点 |
| `question.help` | 题目页提问 | 带入用户作答；先定位考点，再讲解；引用题目解析与知识点 |
| `mistake.review` | 错题本 | 结合历史错因与掌握度讲解 |
| `exam.review` | 考后分析 | 结合试卷错题生成薄弱点总结（数据来自 `learning-profile`） |
| `plan` | 学习计划 | 基于档案生成建议，仅建议非承诺 |

## 5. 回答行为规则（强制）

1. **知识来源**：领域问题必须经 RAG 检索后回答（`rag-knowledge-base`）；检索无结果时明确回答“平台资料未覆盖此内容”，并引导可提问的范围，**禁止编造**。
2. **引用溯源**：回答附带引用（course/chapter/knowledge_point/question 的 id 与标题）；前端渲染“本回答依据：《基础护理学》第三章 第2节”。无引用不出专业结论。
3. **教育性**：答疑先给思路引导，用户可要求完整解析；**禁止代写作业、代考、直接泄露未公开真题答案**（真题发布状态见 `question-bank`）。
4. **大纲优先**：内容与官方考试大纲冲突时，以大纲为准并提示差异。
5. **输出格式**：Markdown；结论在前；公式/表格规范；支持流式（SSE）输出；长度按场景控制（总结 ≤ 300 字，讲解可分段）。
6. **多轮**：会话（session）绑定场景锚点；上下文窗口超限时按“锚点 > 近期对话 > 档案”优先级裁剪，禁止简单截断导致丢锚点。

## 6. 计费联动（强制）

- 每次生成必须经 `token-billing` 预检/预扣/结算；场景与模型在请求中标识。
- 前端在 AI 入口展示余额与本次预估消耗（预估口径由后端给出）。
- 任何“免调用计费”的场景必须在 PRD 与 `token-billing` 中明确配置，禁止代码写死免费。

## 7. 数据流总览

```
前端场景锚点 → 后端 ContextBuilder → 计费预检(预扣) → AI 服务
   (RAG 检索 + 生成) → 流式返回 → 后端结算写流水 → 引用溯源渲染
```

## 8. 禁止事项（NEVER）

- 绕过 RAG 直接自由发挥回答领域问题。
- 把题库/教材全量塞进 prompt（走检索，见 `rag-knowledge-base`）。
- 前端拼接系统 prompt；用户数据跨会话泄露。
- 生成内容无引用溯源；编造出处（“根据教材”但未检索到）。
- 绕过 `token-billing` 的计费链路。

## 9. 与其他 Skill 的关系

- 知识来源：`rag-knowledge-base`；个性化数据：`learning-profile`；计费：`token-billing`；接口：`api-design`（SSE 约定）。
- 产品立项：任何新 AI 场景先走 `product-prd` + `master-orchestrator`。

## 10. 检查清单

- [ ] 场景锚点结构定义完整？前端未拼 prompt？
- [ ] 上下文注入最小化且按用户隔离？
- [ ] 回答带引用溯源？无依据时明确说“未覆盖”？
- [ ] 计费预检/结算链路完整？
- [ ] 流式输出异常（断连/超时）有结算与降级处理？
