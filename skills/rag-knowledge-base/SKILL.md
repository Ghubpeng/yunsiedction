# rag-knowledge-base（课程/题库知识库）

## 1. 定位

平台 AI 的领域知识**唯一来源**。AI 不是“随便问随便答”，而是：官方资料 → 知识处理 → 知识库 → RAG → AI Tutor。设计思想借鉴 [DeepTutor](https://github.com/HKUDS/DeepTutor)（版本化 Knowledge Base、RAG/GraphRAG、Question Bank、Memory），但面向**考试培训**重新设计，不照搬。

## 2. 数据源（白名单，新增需 PRD）

- 官方教材（授权内容）
- 课程视频 + 字幕（ASR 转写）
- 讲义 / 课件
- 题库（题干 + 解析，见 `question-bank`）
- 考试大纲 / 官方考试资料
- 平台自产教学内容

## 3. 知识模型（层级，强制）

```
证书(cert) → 课程(course) → 章节(chapter) → 知识点(knowledge_point) → 题目(question)
```

- 每个 chunk 必须绑定**至少一个知识点**（打标签），禁止无标签切片。
- 题目入库时同步打知识点标签（与 `question-bank` 一致）。

## 4. 处理流水线（强制）

```
采集 → 清洗（OCR/ASR 校对、去噪、格式统一、去重）
     → 切片（语义切片，500–1000 token，重叠 10–15%，按章节/知识点边界）
     → 向量化（embedding 模型统一版本管理）
     → 入库（向量库 + 元数据：source_type/source_id/course_id/chapter_id/
        knowledge_point_id/version/status）
     → 索引（向量 + 关键词 BM25 混合）
```

- 每个 chunk 携带：来源类型（教材/字幕/讲义/题库/大纲）、来源 ID、版本号、生效状态。
- 处理失败可重试、可告警；禁止静默丢弃失败批次。

## 5. 版本化（借鉴 DeepTutor，强制）

1. 教材版本/大纲修订 → 新版本知识库（全量或增量发布），旧版本保留。
2. 引用指向版本：AI 回答的引用必须携带知识库版本。
3. 支持回滚；下线旧版本时先停用索引，再归档，禁止直接物理删除。
4. 过期资料不得混入新版本检索结果。

## 6. 检索（强制）

1. 混合检索：向量 + BM25 + 知识图谱关系扩展（GraphRAG 思路，按需启用）；检索前按**证书/课程过滤**（范围与权限）。
2. 重排（rerank）+ 相似度阈值：低于阈值视为“未覆盖”（见 `ai-tutor` 行为规则）。
3. top-k 与阈值可配置（配置化，运营可调）。
4. 检索必须记录 trace：query → 命中 chunk 列表（供引用溯源与质量监控）。

## 7. 引用溯源（强制）

- AI 回答携带引用：`{source_type, source_id, course/chapter/knowledge_point, version}`。
- 前端渲染：“本回答依据：《基础护理学》第三章 第2节 / 讲义 / 题库解析”。
- 引用数据不允许前端/AI 编造，必须来自检索命中记录。

## 8. 权限与可见范围

- 知识库内容按证书/课程可见范围过滤（学员只能检索其有权访问的课程资料，见 `permission-rbac`）。
- 后台知识库管理（切片、版本发布）权限独立控制。

## 9. 质量与监控

- 切片质量抽检；检索命中率、无结果率、引用覆盖率监控与告警。
- 题目/讲义更新触发增量索引（事件驱动，异步任务）。

## 10. 禁止事项（NEVER）

- AI 绕过 RAG 自由回答领域问题（`ai-tutor` 同款铁律）。
- 未清洗/未打标签的原文直接入库。
- 无版本管理直接覆盖旧资料；物理删除在用版本。
- 引用溯源造假（返回未命中的来源）。
- 把知识库当作普通文件存储（必须有索引与元数据体系）。

## 11. 检查清单

- [ ] chunk 全部绑定知识点/课程层级与版本？
- [ ] 流水线可重试、失败有告警？
- [ ] 检索带过滤/重排/阈值，命中可追溯？
- [ ] 版本发布/回滚流程完整？
- [ ] AI 回答引用全部来自命中记录？
