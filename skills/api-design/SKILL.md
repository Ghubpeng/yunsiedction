# api-design（前后端 API 规范）

## 1. 定位

前后端与 AI 服务间的**唯一接口契约**。所有接口先定文档再写代码；禁止口头约定。

## 2. URL 与动词

```
/api/v1/{domain}/{resource}[/{id}][/sub-resource]
```

- 资源名用**复数名词**：`/api/v1/course/chapters`；动作用子资源或明确动词：`POST /api/v1/exam/papers/{id}/submit`。
- HTTP 方法语义：GET 查询、POST 创建/动作、PUT 全量更新、PATCH 部分更新、DELETE 删除（默认逻辑删除）。
- 分域：`/course`、`/question`、`/exam`、`/ai`、`/pay`、`/user`、`/sys`（与 `database-design` 域前缀一致）。

## 3. 统一响应体（强制）

```json
{ "code": 0, "message": "ok", "data": {}, "traceId": "…", "timestamp": 1700000000000 }
```

- `code = 0` 成功；非 0 为业务错误（码段见下）。
- HTTP 层：业务结果一律 200；401/403 表示认证/授权失败，5xx 表示网关/系统级异常。前端以此分流。
- 时间统一 `yyyy-MM-dd HH:mm:ss`（东八区）；金额/Token 返回字符串化或 Decimal 字符串，防精度丢失。

## 4. 错误码码段（强制）

| 码段 | 含义 | 示例 |
|---|---|---|
| 1xxxx | 认证 | 10001 未登录、10002 token 过期 |
| 2xxxx | 权限 | 20001 无操作权限、20002 越权访问他人资源 |
| 3xxxx | 业务 | 30001 余额不足、30002 考试已交卷、30003 题目不存在 |
| 4xxxx | 第三方 | 40001 AI 服务异常、40002 支付渠道异常 |
| 5xxxx | 系统 | 50001 系统繁忙 |

错误码在代码中集中定义（枚举类），禁止魔法数字散落。

## 5. 分页与查询约定

- 入参：`pageNum`（从 1 起）、`pageSize`（默认 10，上限 100）、排序 `orderBy` 白名单校验（禁止任意 SQL 排序字段）。
- 出参：`{ "list": [], "total": 123 }`。
- 关键字搜索：`keyword` 单参数；模糊查询走索引友好方案（前缀匹配优先）。

## 6. 鉴权

- 用户端：`Authorization: Bearer <accessToken>`；access 短效 + refresh 长效轮换；小程序登录用 `code` 换 token。
- 后台：同一套 token + 角色权限（`permission-rbac`）。
- AI 服务内部接口：仅内网 + 服务间 secret 头；禁止暴露公网、禁止把用户 token 转发给 AI 服务。

## 7. 幂等（强制）

1. 写操作统一支持 `X-Idempotency-Key` 请求头；**支付、计费、交卷必须实现**（服务端存幂等键 → 重复请求返回首次结果）。
2. 唯一性必须有数据库唯一索引兜底（订单号、渠道流水号、request_id）。
3. 重试语义：客户端超时重试必须携带同一幂等键。

## 8. 版本与演进

- 破坏性变更升大版本：`/api/v2/...`，v1 保留过渡期并在响应头标记废弃。
- 字段演进：先加新字段（可选）→ 标记废弃 → 下线；禁止直接删字段/改类型。

## 9. 文档（强制）

- OpenAPI 3：后端 Springdoc 自动生成；AI 服务 FastAPI 自带。文档纳入评审与验收。
- 变更流程：先改 OpenAPI 定义 → 评审 → 再实现；前端以文档为准，禁止“按感觉联调”。

## 10. 禁止事项（NEVER）

- 接口返回直接暴露 Entity/数据库字段命名不一致的裸结构。
- 返回密码、密钥、他人隐私字段；列表接口返回不必要的大字段。
- 用 `success: true` + 字符串拼错误信息这类无码错误。
- 前端自创接口契约、绕过文档。

## 11. 检查清单

- [ ] URL/动词/分域符合约定？
- [ ] 响应体、错误码码段合规？traceId 透传？
- [ ] 分页参数有上限？排序字段白名单？
- [ ] 支付/计费/交卷接口幂等且唯一索引兜底？
- [ ] OpenAPI 文档已更新并评审？
