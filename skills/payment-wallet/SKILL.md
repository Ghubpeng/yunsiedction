# payment-wallet（平台币 / VIP / 订单）

## 1. 定位

平台币钱包（Token 余额）+ VIP + 订单 + 支付渠道。**资金安全第一**：金额精确、回调幂等、流水可对账、全程审计。

## 2. 账户模型（要点）

```
user_wallet   钱包（user_id、balance 平台币 DECIMAL(18,4)、
              vip_level、vip_expire、status、version 乐观锁）
```

- 平台币与 Token 的兑换关系**配置化**（如充值 1 元 = 1000 tokens 由充值商品定义），AI 计费消耗见 `token-billing`。
- 余额变更必须：条件更新（防负）+ 流水 + 审计。

## 3. 订单状态机（强制）

```
创建 → 待支付 → 已支付 → 已完成
         ↘ 已关闭（超时未支付/用户取消）
已支付 → 退款中 → 已退款（部分退款记录金额）
```

- 非法状态转换一律拒绝；状态变更必须记录时间与操作来源。
- 订单号规范：`yyyyMMdd + 业务码 + 序列`，唯一索引兜底。

## 4. 支付流程与回调（强制）

1. 下单：金额以**服务端商品配置**为准（禁止采信客户端传入金额）。
2. 支付：渠道下单 → 用户支付 → 渠道异步回调（决策点 #8：微信/支付宝）。
3. 回调处理（必须按序）：
   - ① 验签（渠道签名校验，失败直接拒收）
   - ② 幂等：按渠道流水号唯一索引去重（重复回调返回成功，不重复入账）
   - ③ 金额校验：回调金额 = 订单金额，不一致挂起告警
   - ④ 入账：订单状态条件更新（待支付 → 已支付）+ 钱包入账 + 流水，同一事务
   - ⑤ 渠道重试：回调失败返回失败让渠道重试；处理成功返回成功
4. 主动查单兜底：超时未回调 → 定时任务向渠道查单，闭环对账。

## 5. 退款（强制）

- 原路退回；退款幂等（退款单号唯一）；支持部分退款（记录累计退款金额，不得超过实付）。
- AI 计费的“失败退款”是平台内余额退还（`token-billing`），与渠道退款区分。

## 6. VIP 与权益（强制）

- VIP 权益全部配置化：`vip_rights`（权益码、参数、生效条件）。
- 权益判断统一入口 `RightsService`（`permission-rbac`）；业务代码禁止 `if (vipLevel == 2)`（`project-architecture` 铁律 2）。
- VIP 到期定时任务处理；续费叠加规则配置化。

## 7. 对账与审计

- 每日与支付渠道对账（订单、金额、退款），差异告警人工处理。
- 所有资金变动：操作人、时间、前后值、流水号；调账必须走专用接口 + 双人复核（后台）。

## 8. 禁止事项（NEVER）

- 金额用 float/double；采信客户端金额。
- 回调不做验签/幂等；回调里做重业务（应异步处理，回调只落账）。
- 手工改余额；订单状态跳变。
- 权益判断散落在业务代码。

## 9. 与其他 Skill 的关系

- AI 消费流水：`token-billing`；权益判断：`permission-rbac`；事务并发：`backend-development`；数据模型：`database-design`（`pay_` 域）；测试：`testing`（支付必测清单）。

## 10. 检查清单

- [ ] 订单状态机完整，非法转换被拒？
- [ ] 回调：验签 → 幂等 → 金额校验 → 事务入账 四步齐全？
- [ ] 超时查单兜底与每日对账到位？
- [ ] 退款幂等、累计退款不超实付？
- [ ] VIP 权益配置化 + RightsService 统一入口？
