# testing（测试规范）

## 1. 定位

质量门槛：**核心链路不测不交付**。测试在开发收尾时执行（`master-orchestrator` 流程最后一步），修改共享模块时必须跑回归。

## 2. 测试分层

| 层级 | 覆盖 | 工具（默认） |
|---|---|---|
| 单元测试 | Service 核心逻辑：计费结算、组卷算法、掌握度计算、权益判断 | JUnit 5 + Mockito |
| 接口测试 | Controller 契约、鉴权、参数校验 | Spring Boot Test / MockMvc |
| 前端测试 | 关键交互组件（答题、表单校验、AI 面板） | Vitest + Testing Library |
| E2E | 核心用户链路 | Playwright |

## 3. 必测清单（强制，对应各领域 Skill）

1. **token-billing**：同一 request_id 重放不重复扣费；并发扣费无负余额；AI 失败全额退款；流式断连按 usage 结算；预扣多退少补。
2. **payment-wallet**：回调重复不重复入账；回调金额与订单不符拒收；订单非法状态转换被拒；退款累计不超实付。
3. **permission-rbac**：每个涉及他人资源的接口的横向越权用例（A 访问 B → 403）；教师数据范围隔离；按钮/菜单权限双端一致。
4. **exam-engine**：重复交卷返回首次结果；并发交卷只计一次分；超时自动交卷；组卷种子可复现、无重复题。
5. **question-bank**：导入校验逐行报错、部分失败不入库；已发布题目修改走新版本。
6. **learning-profile**：事件幂等（重复上报不重复计数）；掌握度计算可追溯。
7. **ai-tutor**：无检索命中时不编造；引用来自命中记录；跨用户数据不泄露。

## 4. 覆盖与回归要求

- 核心模块（计费/支付/权限/考试）行覆盖率 ≥ 80%。
- 修改共享模块（权益、计费、题库、权限、钱包）必须跑完整回归清单（`master-orchestrator` 变更影响清单的用例）。
- 上线前核心链路冒烟：注册登录 → 购课/充值 → 学习 → AI 答疑 → 考试 → 档案更新。

## 5. 禁止事项（NEVER）

- 只测 happy path；用生产数据做测试。
- 计费/支付/权限/交卷改动不补用例直接交付。
- 测试里 mock 掉被验证的核心逻辑（如把扣费方法整个 mock 掉再测计费）。

## 6. 检查清单

- [ ] 本次改动对应的必测清单项全部有用例？
- [ ] 覆盖含异常/并发/幂等/越权分支？
- [ ] 共享模块改动已跑回归？
- [ ] 上线前冒烟通过？
