# admin-development（SmartAdmin 风格后台）

## 1. 定位

管理后台遵循 **SmartAdmin 风格**：经典三段式布局 + 标准化表格页范式，**效率与稳定性优先**，不做花哨动效。

## 2. 布局范式

```
┌──────────┬──────────────────────────────┐
│  侧边栏   │  顶栏（面包屑 / 用户 / 操作）  │
│ （可折叠）├──────────────────────────────┤
│  菜单树   │  多标签页（Tab 页签）          │
│          ├──────────────────────────────┤
│          │  页面 = 搜索区 + 工具栏 + 表格  │
└──────────┴──────────────────────────────┘
```

- 侧边栏：按业务域分组菜单树，可折叠；菜单由权限动态生成（`permission-rbac`）。
- 顶栏：面包屑、全屏、主题、用户信息。
- 多标签页：路由缓存（keep-alive 等价物），关闭标签页即释放。

## 3. 表格页标准范式（所有列表页必须遵守）

1. **搜索区**：条件收敛在关键字段（时间范围、状态、关键字），默认收起高级项；搜索/重置按钮。
2. **工具栏**：新增、批量删除/审核、导入、导出、刷新；按钮按权限点显示（`permission-rbac`）。
3. **表格**：列宽合理、金额/时间右对齐、状态用标签色（字典驱动）；行操作（编辑/删除/详情）固定右侧。
4. **分页**：服务端分页，参数见 `api-design`。
5. **表单**：新增/编辑用弹窗或抽屉，提交前客户端校验 + 服务端校验双保险。
6. **详情**：抽屉展示，关联数据（如题目关联知识点）用表格/Tag 呈现。

## 4. 后台专属规则（MUST）

1. 菜单级 + 按钮级权限双重控制；无权限的菜单不渲染、无权限的按钮不显示，且服务端强制校验。
2. 敏感操作（删除、审核、调价、退款、改余额）必须二次确认 + 操作审计日志（谁/何时/改了什么/改前改后值）。
3. 数据权限：教师只能看到/管理自己负责课程的资源；实现走统一 DataScope（`permission-rbac`），禁止散落 if 判断。
4. 表格大数据量必须服务端分页 + 虚拟滚动兜底；禁止一次性拉全量。
5. 导入必须校验并回写错误行报告（见 `question-bank` 的 Excel 导入规范）。
6. 字典（状态、题型、难度、审核状态等）统一走字典表/接口，禁止前端写死枚举文案。
7. 后台页面**禁止装饰性动效**；React Bits 组件不用于后台核心操作区（Loading/空态可用静态样式）。

## 5. 审计与安全

- 操作日志：登录、删除、审核、调价、退款、权限变更、导入导出。
- 禁止在后台明文展示敏感信息（手机号、Token 余额可配置脱敏展示）。
- 后台接口同样必须防越权：每个接口的横向越权用例见 `permission-rbac`。

## 6. 禁止事项（NEVER）

- 后台页面加动画/炫技组件。
- 前端权限当安全边界（服务端必须校验）。
- 全量拉数据到前端再“前端分页”（大表场景）。
- 硬编码字典、状态枚举、菜单（菜单走权限配置）。
- 无审计的敏感操作。

## 7. 与其他 Skill 的关系

- 工程基础：`frontend-development`（叠加使用）。
- 接口：`api-design`；数据：`database-design`；权限：`permission-rbac`。
- 视觉：`frontend-design-system` 中“后台=效率优先”的约束。
