# learning-profile（学习档案 / 知识掌握度）

## 1. 定位

统一学习档案：记录“学过什么、会什么、错在哪、习惯如何”，是 AI 个性化学习与考试预测的数据基础。设计思想借鉴 [DeepTutor](https://github.com/HKUDS/DeepTutor) 的 Memory / Mastery Path，面向考试培训重新设计。

## 2. 档案模型

```
User Learning Profile（用户学习档案）
    ├── Learning History  学习历史（时长、课程完成度、刷题量、计划）
    ├── Mastery           知识点掌握度
    ├── Weakness          薄弱点（低掌握度 + 高频错题）
    ├── Strength          强项
    ├── Behavior          行为（连续学习、时段、AI 使用情况）
    └── Exam Prediction   考试通过率预测（仅参考）
```

## 3. 采集字段（强制）

| 字段 | 来源 |
|---|---|
| 学习时长 | 视频观看事件（心跳/进度） |
| 课程完成度 | 章节完成事件 |
| 刷题量 / 正确率 | 答题记录（练习、考试） |
| 错题 | 答题记录（错题本） |
| 考试成绩 | `exam-engine` 成绩事件 |
| 知识点掌握度 | 由答题表现计算（见下） |
| 连续学习 | 学习事件日历 |
| 学习计划 | 计划创建/完成事件 |
| AI 使用情况 | `token-billing` 流水聚合 |

## 4. 采集机制（强制）

1. **事件驱动**：学习行为事件 → 消息队列/异步任务 → 档案聚合更新。禁止在用户主流程里同步算档案（不阻塞答题/交卷/视频）。
2. 关键事件（交卷、完成章节、错题）必须产生；重复上报幂等（事件去重键）。
3. 防刷：时长/刷题事件带会话标识与合理阈值（策略配置化），异常事件标记不计数。
4. 最终一致：档案允许秒级延迟；禁止要求强一致导致主链路阻塞。

## 5. 掌握度计算（强制）

1. 按**知识点**维度计算（user × knowledge_point），初始 0。
2. 规则：答题正确加权上升、错误下降；多次正确巩固；**时间衰减**（久未练习缓慢下降，参考艾宾浩斯曲线）。
3. 权重与衰减参数**配置化**（`sys` 配置表），算法本身集中在一个模块，禁止散落实现。
4. 掌握度变化必须可追溯（计算依据：哪次答题/考试触发）。

## 6. 数据访问权限（强制）

- 本人：全量查看自己的档案。
- 教师：仅自己负责课程范围的学员档案（DataScope，`permission-rbac`）。
- AI 服务：经内部 API 读取**最小必要字段**（`ai-tutor` 上下文注入），禁止全量拉取。
- 前端：只暴露视图所需字段，禁止任意拼装查询。

## 7. 考试预测（约束）

- 预测仅作参考展示（如“按当前掌握度预计通过率 XX%”），**禁止承诺性表述**。
- 预测模型/规则版本化，可回溯；预测不参与任何自动决策（如强制购课）。

## 8. 禁止事项（NEVER）

- 同步阻塞主流程计算档案。
- 掌握度算法散落多处/参数硬编码。
- 档案跨用户泄露（AI 上下文/教师视图）。
- 预测结果当权威结论展示。
- 事件采集无幂等导致重复计数。

## 9. 与其他 Skill 的关系

- 事件来源：`exam-engine`、答题记录、视频进度。
- AI 个性化注入：`ai-tutor`；AI 使用统计：`token-billing`；权限：`permission-rbac`；数据模型：`database-design`（`learn_` 域）。
