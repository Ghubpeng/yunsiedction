# exam-engine（模拟考试 / 随机组卷 / 计时）

## 1. 定位

模拟考试全流程：组卷 → 考试会话 → 作答保存 → 交卷 → 判分 → 成绩。核心原则：**服务端时间与状态为准，试卷快照不可变，交卷幂等**。

## 2. 数据模型（要点）

```
exam_paper_template  试卷模板（组卷规则：题型/知识点/难度/数量配额、总分、时长）
exam_paper           试卷实例（快照：题目内容、顺序、版本；生成后不可变）
exam_record          考试记录（用户、试卷、开始/结束时间、状态）
exam_answer          作答明细（每题答案，按需分表）
exam_score           成绩（总分、正确率、知识点得分，写入 learning-profile）
```

- 试卷实例必须**快照题目**（题干/选项/答案/解析在生成时复制），题库后续改题不影响历史试卷（`question-bank` 版本机制兜底）。

## 3. 组卷（强制）

1. 规则组卷：按题型 + 知识点 + 难度 + 数量的配额抽取（配额可配置，运营可调）。
2. 随机抽取使用**可复现种子**（seed 落库），便于复核与问题定位；同一卷内禁止重复题。
3. 支持固定卷（人工选题）。
4. 抽取失败的兜底：配额不足时按规则降级（如放宽难度）并记录警告，禁止静默塞无关题。

## 4. 考试会话（强制）

1. 开始考试生成考试记录（状态：进行中）；**计时以服务端时间为准**，前端只做倒计时展示。
2. 作答实时/定时保存（断点续答）；每题作答带客户端时间戳（仅作异常检测参考，不作判分依据）。
3. 超时自动交卷（定时任务兜底 + 客户端到时触发交卷双保险）。
4. 状态机：进行中 → 已交卷 → 已阅卷；非法状态转换拒绝（已交卷不得再作答）。

## 5. 交卷与判分（强制）

1. 交卷**幂等**：重复交卷请求返回首次结果；交卷请求带幂等键（`api-design`）。
2. 客观题自动判分；主观题初期人工阅卷，AI 辅助阅卷需人工复核（决策点 #9）。
3. 交卷并发：条件更新状态（`where status = 进行中`），受影响行数为 0 → 已交卷，返回既有结果。
4. 成绩落库后触发 `learning-profile` 更新（异步事件）。

## 6. 防作弊（基础能力）

- 切屏/离开检测：前端上报事件，服务端记录（策略配置化：警告/标记/强制交卷）。
- 作答时间异常（如毫秒级秒答）标记，供人工复核。
- 防作弊能力按 PRD 逐步建设，禁止以“防作弊”为由无限加功能（`product-prd`）。

## 7. 禁止事项（NEVER）

- 以客户端时间为准（计时/超时/交卷）。
- 试卷实例引用题库原题而不快照。
- 重复交卷重复计分；交卷不幂等。
- 组卷失败静默塞题；配额规则硬编码。
- 成绩不写 `learning-profile` 事件。

## 8. 与其他 Skill 的关系

- 题目与解析：`question-bank`；成绩入档案：`learning-profile`；接口幂等：`api-design`；并发与事务：`backend-development`；测试用例：`testing`。

## 9. 检查清单

- [ ] 试卷快照不可变？组卷种子可复现？
- [ ] 计时/交卷以服务端为准？交卷幂等？
- [ ] 状态机完整，非法转换被拒？
- [ ] 成绩事件触发档案更新？
- [ ] 防作弊策略配置化？
